开发一个基于 React + TypeScript + React Flow 的交互式业务状态机可视化工具，用于辅助 AI 理解和修改现有 Java Spring Boot 项目。

核心要求：

1. 代码驱动状态机：以现有代码为事实来源，分析 Java Service、状态枚举、数据库操作和 Kafka Consumer，提取业务状态及流转关系，不要求重构现有代码。
2. 交互式可视化：通过网页展示状态节点和流转路径，支持拖动、缩放、点击查看触发条件及对应代码位置。
3. AI 变更预览：AI 修改 Jira 需求前，先展示预计新增、删除、修改的状态及路径，使用不同颜色标注，供开发者确认。
4. 代码变更验证：修改完成后，根据 Git Diff 重新分析状态机，对比预期与实际变化，标记不一致的地方。
5. 多 Repo 支持：支持 VS Code Multi-root Workspace，分析跨 Repo 的 API、Kafka 消息及上下游依赖。
6. 业务规则追踪：关联 Jira 需求、代码位置和 Git Commit，区分当前代码行为与目标业务行为，保留历史变更记录。
7. AI 集成：提供 MCP Server 或标准化接口，让 VS Code AI Agent 可以读取状态图、提交变更提案和触发重新分析。

设计原则：

* 不侵入现有业务代码。
* 不允许 AI 擅自认定业务规则正确性。
* 无法确认的状态流转必须标记为待人工确认。
* 优先本地运行，不上传内部代码。
* 保持架构轻量，先实现可运行的 MVP。

请先分析技术可行性和项目架构，再实现第一版 MVP。第一版重点完成状态图展示、手动编辑、JSON 持久化、AI 变更提案及可视化 Diff，不必一次性实现完整的 Java 静态分析和 Jira 集成。
